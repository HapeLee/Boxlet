# ADR 0001：Boxlet 默认端口使用 53318

- 状态：已采纳
- 日期：2026-10-21

## 背景

Boxlet 的协议报文格式对齐 LocalSend v2.2，早期直接沿用官方默认端口 `53317`（TCP 服务端 + UDP 多播监听同端口）。

真机实测暴露冲突：同一台 Android 设备上安装官方 LocalSend 后，两应用无法同时运行。先启动的一方占住 `53317`，后启动方在 `Address already in use` 上失败。例如官方客户端在后台保活时启动 Boxlet，界面上出现：

```
无法启动接收服务: bind failed: EADDRINUSE (Address already in use)
```

Boxlet 的目标是自己的 Android / 桌面 / 无头引擎闭环，官方客户端只作为协议参考，不需要默认与官方客户端并存于同一端口。

## 决策

- `Protocol.DEFAULT_PORT` 由 `53317` 改为 `53318`。
- 保留 `Protocol.LOCALSEND_PORT = 53317` 作为显式的互通端口常量，设置页仍可手动把端口改回 `53317`。
- 协议报文中的 `port` 字段继续如实上报本机实际端口，字段与格式不变。

## 后果

正面：

- Boxlet 与官方 LocalSend 可在同一台设备、同一局域网共存，互不抢端口。
- 多台 Boxlet 之间完全不受影响：端口随 announce 报文传递，接收方按 `message.port` 回连。

负面：

- 默认配置下**不再与官方客户端互相发现**。UDP 多播 socket 绑定在本机端口上，端口不同时双方收不到彼此的 announce；`/24` 扫描回退同样按本机端口发起，因此也无法补齐。
- 与官方客户端互通需要双方显式统一端口：把 Boxlet 端口改成 `53317`，且不要在同机运行官方客户端。
- 已安装过的实例会把旧值 `53317` 持久化在设置里，改默认值不会覆盖它；需要用户手动改端口或清除应用数据。

## 被否决的方案

- **双端口监听**：同时绑定 `53318` 与 `53317`，在 `53317` 上只做发现。可行但显著增加 socket 生命周期复杂度，且 `53317` 被官方客户端占用时仍然失败，收益有限。
- **端口自动探测**：启动失败时顺延端口。会让“设备曾经在哪个端口”变得不可预测，且跨进程重启后端口漂移，对接收方不友好。
