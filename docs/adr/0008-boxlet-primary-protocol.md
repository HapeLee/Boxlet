# ADR 0008：BP/2 为主协议，LocalSend 为默认启用的兼容层

> 2026-10-25 当前产品决策：默认使用标准 LocalSend，BP/2 默认关闭，三端不提供其开关、端口或状态设置；BP/2 实现与测试保留为内部实验。下文保留阶段设计和迁移记录，当前实现以 [实现记录](../protocol/IMPLEMENTATION.md) 为准。

- 状态：已采纳；阶段 A 已实现，原生 BP/2 默认启用，浏览器迁移与完整验收待完成
- 日期：2026-10-23
- 规范：[Boxlet Protocol 2](../BOXLET-PROTOCOL-2.md)
- 替代：ADR 0005 的未来主协议方向；ADR 0007 的 Boxlet 私有扩展长期定位

> 同日修订：按用户要求，LocalSend 从“默认关闭、手动开启”调整为“默认启用、统一发现、自动按目标协议发送”。统一路由与后续 Quick Share 扩展见 [ADR 0009](0009-unified-device-discovery-and-routing.md)。协议隔离不等于让用户手动切模式。

## 背景与决定

项目尚未对外发布，不承担旧版 Boxlet 兼容成本。现有原生主链路是 LocalSend v2.2，浏览器使用 SP/1；ADR 0007 虽实现流式校验，仍寄生在 LocalSend 上传接口上。继续加私有字段会把自有协议与兼容模式混在一起。

统一采用 BP/2：原生 TLS 长连接，浏览器 WSS，同一套带 streamId/offset 的帧、分页清单、BATCH 小文件、分块 SHA-256、接收信用、暂停和续传。版本直接升至 2，避免与现有 SP/1 隐式流归属混淆。LocalSend 作为默认启用、可独立关闭的兼容适配器，与 BP/2 一起发现设备；选中 LocalSend 设备即自动使用其协议。

## 关键取舍

- 正常首次发送只读一次源文件；分块摘要与 contentRoot 不要求整文件预哈希。续传时为了避免源文件变化拼接旧内容，默认重读校验已保留前缀。
- 默认一条 TCP/TLS 加密连接，多流调度，不引入单文件多连接。2026-10-24 对照实验后按用户要求撤除 QUIC 代码、依赖与入口，统一维护 TCP/TLS 数据链路；UDP 仅用于发现。TCP 队头阻塞仍存在，性能优化继续以流水线、确认调度与存储实测为依据。
- 用 BATCH 减少小文件的应用请求次数，不先压缩或落临时 ZIP；目录结构与逐文件结果保留。
- ACK、written、durable、FILE_DONE 分开，接收信用限制全部流共享的内存。不能用浏览器本地 bufferedAmount 代替远端背压。
- 默认开启加密与完整性校验。浏览器 WSS 的证书信任是明确的实现依赖，不能靠原生证书指纹规则或明文降级绕过。
- 主协议不兼容 SP/1/早期 Boxlet；LocalSend 适配器保持标准格式，不承载 Boxlet 私有扩展。

## 实施顺序与退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| A | commonMain 的 BP/2 模型、帧编解码、摘要算法、独立测试向量 | JVM/Wasm 的线格式与摘要逐字节一致，边界/坏帧测试通过 |
| B | 原生 TLS transport、认证发现、单文件/双向会话、临时文件提交 | Android ↔ Windows 大文件校验与取消通过；原生默认启用与真机验收分别记录 |
| C | 分页清单、BATCH、公平调度、信用、状态索引 | 大清单与慢磁盘测试内存有界，小文件实测与旧路径公平对比 |
| D | 暂停、检查点、续传、幂等完成 | 断线/重启/源变化/丢失最终回复的恢复通过 |
| E | 浏览器 WSS 可信证书接入、发送与条件接收 | >2 GiB 与浏览器文件 API 权限恢复通过；不可接收时准确公告能力 |
| F | 默认主链路切换、统一设备目录与路由、默认启用的 LocalSend 适配器、旧代码清理 | 原生与浏览器分阶段迁移；LocalSend 默认发现/发送/接收、双协议去重及端口冲突测试通过，完整验收条件单独跟踪 |

2026-10-24 实现进度和可重复验证命令见 [实现记录](../protocol/IMPLEMENTATION.md)。阶段 A 已有 JVM/Wasm 实现与独立黄金向量验证；后续阶段的组件测试通过不等于完整任务状态机或真机验收已通过。

同日继续：名称统一为 Boxlet Protocol / BP/2，公开前同步调整线格式标识、摘要域与 API 命名。阶段 D 已实现任务暂停/继续、持久化接收清单与选择、检查点、源前缀比较、RESUME/READY、自动重连三次及耗尽后的手动恢复。普通文件系统接收端仅在实际支持安全原子发布时公告 `resume`；文本及 Android SAF/MediaStore 接收暂不签发恢复凭证。两进程 256 MiB 传输中分别重启接收端、发送端后的续传、SHA-256 与历史去重已验证。发送端加密保留凭证/清单/本机 source 引用，启动恢复为 PAUSED，显式继续才重新认证和验证源前缀；Android 已接入持久读取授权的 source resolver，但尚未真机验收。已补上前缀变化时保留暂停、明确选择逐文件重置及重置后断线恢复；更多 provider、逐文件暂停/取消和 WSS 等退出条件仍未全部完成。

阶段 F 时移除 ADR 0007 私有 capability/尾摘要、预哈希回退分支；标准 LocalSend 的预哈希仅留在兼容适配器。阶段 F 前不能只改版本常量/README 就声称运行时已换协议，也不能提前删除仍在使用的链路。

建议代码边界：`core/protocol/bp2` 放公共 wire 模型/codec，`core/transport` 放 TLS/WSS 载体，`core/session` 放传输/流控/续传，`core/compat/localsend` 放标准适配器；统一 `DeviceDirectory`、`ProtocolRegistry`、`TransferRouter` 连接各适配器，平台提供受限 source/destination 能力，UI/IPC 依赖统一任务模型。此为后续重构目标，现有目录无需在文档阶段空搬。

## 当前事实

2026-10-24：BP/2 已实现原生 TLS 双向会话、分页 OFFER/ACCEPT、BATCH、信用背压、坏块修复、持久化接收续传，并接入实际发送、接收确认、存储、历史与协议自动路由。双进程验证包含双方分别重启后恢复和文件/历史去重。原生应用默认启用 BP/2，已有显式关闭设置保持关闭；LocalSend 默认启用，使用标准报文与默认 TCP 53317，BP/2 使用 TCP 53318。Android、Compose 桌面与 WinUI 共用接收确认、收藏和快速保存规则；更多 provider、Android 权限恢复真机验证、WSS、大清单磁盘索引与真机无线验收待完成，因此阶段 B/C/D/F 仍不能标为全部完成。浏览器仍为 SP/1。

本次根据用户继续优化并争取默认使用的要求，将原先原生/浏览器一次性迁移调整为分阶段迁移：原生先默认启用已实现的 TCP/TLS 会话，最初须双方核对完整指纹并登记信任。2026-10-25 按用户反馈移除单独的配对与指纹名单，经过 TLS/HELLO 验证即可优先使用 BP/2，接收权限统一使用现有接收确认、收藏设备自动接收和快速保存规则。仅支持 LocalSend 的设备继续标准兼容。浏览器继续 SP/1，直到 WSS 的证书与文件权限恢复独立验收。原生默认配置切换不等于全部规范完成或已证明吞吐优于 LocalSend。
